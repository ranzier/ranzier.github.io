novel-agent微调教程

novel-agent微调教程

1. 微调的场景与目标

1.1 场景

现有长篇中文小说 Agent 虽然通过提示词约束去除 AI 腔，但生成章节中仍会出现模板化句式、空泛心理描写、机械转折和过度解释等问题。

  • 仅仅通过提示词工程的约束无法完全消除AI味的句子的生成。

1.2 目标

因此计划使用 Qwen3-8B，在 A10 22GB GPU 上通过 LoRA 微调一个“局部文学编辑器”。它接收目标段落及前后文，只对句子或段落做最小幅度改写：

  • 去除明显 AI 腔；
  • 保持人物、剧情、时间、数字、境界、道具和因果关系不变；
  • 不新增剧情、不续写、不解释；
  • 原文自然时保持原样。
    最终目标是把它接入现有小说生成流程，在章节生成后对高风险段落进行局部润色，使成稿更自然、更像人工写作，同时不破坏长篇小说的一致性。

1.3 现在已有的可以解决该问题的技术

A. 使用skill去AI味：

humanizer

Humanizer 是一款面向 Claude Code / OpenCode 环境的开源 Skill 插件，核心作用是识别并消除 AI 生成文本中的典型写作痕迹，将文本改写得更自然、更贴近人类真实写作风格。

局限性

  • 本质是规则化指令工程，存在效果天花板：属于Skill 级别的指令工程
  • 场景偏向通用非虚构文本，文学创作适配性极差：完全没有覆盖小说、散文等文学体裁的典型 AI 问题
  • 原生仅适配英文，中文场景效果大幅打折

B. 现有微调模型去AI味

魔搭社区官方发布过《我们给大模型去掉了 “AI 味”》实战教程:

我们给大模型去掉了“AI味”-大模型微调全链路实战

  • 基于 LoRA 技术微调大模型，让输出文本减少标准化 AI 腔，更贴近人类口语 / 写作风格
  • 教程实测微调后模型的 AI 感明显降低

局限性

  • 训练目标是通用评论风格，不是小说场景的局部改写，也不做 “事实不变” 约束
  • 训练的数据集不贴合网文写作的内容

Qwen 系列网文写作 LoRA：基于 Qwen2/Qwen3 基座微调，覆盖男频、女频、玄幻、现实等题材，训练数据为优质人类网文正文，能让生成文本更符合网文叙事节奏，减少通用 AI 的书面化腔调和空泛描写。

1.4 微调模型 vs 中文大模型

只针对段落为整体的内容进行改写

微调模型不一定要比先进大模型“写得更好”，它的价值可以是更便宜、更稳定、更快、更可控。

3. 选择微调的基础模型

最终选择：

  1. 使用Qwen/Qwen3-8B

资源限制

  1. 受制于硬件GPU显存等的限制，这里最多选择一个7b参数量左右的小模型
  2. 因为写的小说是中文网文，所以最好选择中文模型

选型优点

  1. 中文能力和中文网文表达较稳定；
  2. 是Instruct模型，指令遵循能力比 Base 模型好，适合“只改写目标段落、不能改变事实”；
  3. 文本理解能力比qwen2.5-7b-instruct更强
  4. 你的任务不是从零创作，而是“理解上下文后做局部编辑”，8B 足够
  5. ModelScope、Transformers、ms-swift 生态成熟；支持 LoRA/QLoRA；

4.2 数据集格式的建议

  1. system固定，instruction尽量短一些
  2. input的文本长度（这个尽量对应后续真实改写时的上下文长度）
    • 70%：单句、短句改写
    • 30%：几百字段落改写样本，平衡长短，防止模型只会输出短句
  3. 加入原样保留样本,必须占比30%左右: input和output一样
  4. 训练和实际推理的输入形式必须一致
  5. system固定写入硬约束：不得改变事实、不得改变剧情、不得改变专名和数字等
  6. instruction 最好使用有限、稳定的几类要求
    • 去除空泛心理描写
    • 删除重复动作
    • 减少机械转折
    • 压缩解释性句子
    • 让对白更自然
    • 调整句子节奏
    • 保留原文，不做修改
  7. input中的文本必须完整
    • 完整的一句话
    • 完整的几句话
    • 完整的一个段落

4.3 第一版数据集构造格式示例

  • system和instruction都固定
  • input是输入的原文内容
  • output是润色改写后的文章内容

C. 样本偏差：长度和内容要接近真实使用场景

最重要的是，训练集要接近未来真实输入
网文小说的特点就是以段落为一个整体内容

长度比例：

  • 80%：完整段落
  • 20%：单独句子或几个短句

D. 多样性：针对多种题材的网文内容

不仅要支持历史小说、还支持玄幻、都市、言情等题材的小说

增加多来源、多题材数据。 至少覆盖现代都市、玄幻、科幻、悬疑、言情、轻松对白、第一人称和不同叙述密度，避免把任务等同于“古风化”。
